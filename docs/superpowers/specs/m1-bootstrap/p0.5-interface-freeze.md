# P0.5 · 接口补全 + 硬件画像 + 双模型预留 / 接口冻结

> 设计来源:`docs/readme.md` §16(P0.5)、§3、§4。本阶段不新增推理能力,**只冻结接口**、铺满空实现与默认方法,使后续 P1–P18、T/V/converter 的接口契约全部确定。

## 1. 目标与验收(DoD)

- **目标**:全部接口 100% 定义,空实现/默认方法齐全;双模型(传统+Transformer)、训练、校验、转换、规则、混合等所有预留接口在**编译层可达**。
- **验收标准**:
  1. **接口契约测试通过**:列出全部公开接口并逐一验证能编译、能被空实现实例化、调用时返回合理默认/Unsupported。
  2. 双模型相关新增字段全部落地:`ModelKind`、`OpType` 传统算子族(Conv2D/LSTM/GBDT…)、`MemoryKind::WEIGHT_CONST/KV_CACHE`、`MemoryPolicy`。
  3. `FeatureFlags` 默认值符合 §12.3(`enable_experimental/fp8/speculative/paged/moe/training/...=false`,`enable_capability_driven_selection/runtime_autotuning=enable_conv_winograd/enable_int8_ptq/enable_flash_attention/enable_kv_cache_quant=true`)。
  4. 训练/校验/转换/规则/混合模块**存在且接口完整**(实现可为空),加载开关默认关闭。
  5. API 版本宏与 C ABI 声明落地(`IE_API_VERSION_MAJOR/MINOR`、`ie_create_backend/ie_destroy_backend/ie_api_version`,§12.4)。

## 2. 范围与边界

- **范围内**:接口冻结、空实现、双模型预留字段、FeatureFlags、C ABI 声明、模块骨架目录。
- **范围外**:任何真实 kernel/算子/调度/训练/校验逻辑实现——一律留到对应里程碑。
- **边界**:P0.5 **之后不允许再改已冻结接口**;仅允许新增(如插件/新算子),不允许破坏既有调用。

## 5. 实现要点

- **默认实现语义**:`backward` → `Unsupported("backward not implemented")`;`execute_subgraph` → `Unsupported`;`KVCachePlugin` 扩展方法返回空/`{}` 默认(§3.1)。
- **模型类别贯通**:`OptimizationPlanner::plan/plan(...)`、`KernelVariantSelection`、`RuntimeAutotuner`、`TraceExporter::set_model_kind`、`Experiment.config.model_kind` 都接收 `ModelKind`(仅作策略筛选)。
- **C ABI**:头文件用 `extern "C"` + `IE_API` 导出;版本宏落地。
- **特性门控**:`FeatureFlags` 集中在 `core/config` 或等价处,作为全局编译期/运行期可切换开关。

## 6. 测试与验证

- **接口契约测试**:对每个公开接口生成"可编译/可实例化/默认行为合理"的三元断言;自动收集接口清单并断言 100% 覆盖(=编译期内能遍历)。
- feature flags 默认值断言。
- C ABI 函数存在性(链接期)与 `ie_api_version()` 返回值断言。
- 类型/枚举完整性:走查 OpType、ModelKind、MemoryKind、DType、BackendKind、Plugin 类清单是否与设计一致。

## 7. 依赖

- 依赖 P0-MVP(核心基础类型与骨架)。
- 本阶段结束 = **接口冻结点**,后续里程碑全在这一契约上增量实现。
- 训练/校验/转换 T/V/converter 的接口契约在此阶段锁定,其实现按各自里程碑进行。

## 8. 决策点(默认建议 · 待实现时裁定)

> 记录于 2026-10-18,为**默认建议**而非硬约束;实现 P0.5 时在实现内裁定并回写。

| 决策点 | 默认建议 | 副作用/影响 |
|---|---|---|
| `Graph::bind` 动态绑定 | **对齐 MLIR 动态 shape** | 动态维度绑定走 MLIR 动态 shape/value 机制;与"引入 MLIR"候选联动;若实现时不用 MLIR 则换自定义绑定 |
| 插件 ABI 边界 | **提前锁定** | 本阶段锁定"C ABI + C++ 内部接口 + 语义化版本契约"(§12.4/§18);后续 P17 只填充 `load_shared_library`/加载器 |
| IR 序列化 | JSON(候选) | 加载器/中间产物/GraphExporter 用 JSON |

### 插件 ABI 锁定要点(若采纳"提前锁定")
- 导出面:`ie_create_backend / ie_destroy_backend / ie_api_version`,`IE_API_VERSION_MAJOR/MINOR`(§12.4)。
- 版本契约:语义化版本 + 兼容性检查;load 不兼容插件须给出清晰错误并回退安全路径(§19)。
- 插件句柄生命周期规则在 `PluginRegistry` 文档固定,避免 P17 返工。

### 实现期裁定(2026-11-04,P0.5 完成)

> 依据本阶段实际落地的接口与测试,对 §8 决策点逐项裁定;后续里程碑只允许**新增**,不得破坏以下已冻结调用。

| 决策点 | 实现期裁定 | 落地位置 / 备注 |
|---|---|---|
| `Graph::bind` 动态绑定 | **不引入 MLIR**。保留自定义 `Graph::bind(const ShapeMap&) -> Result<BoundGraph>`;动态维度由 `Graph::DynamicDim` 描述,静态绑定走 `BoundGraph::shapes`。 | `src/core/ir/graph.h`、`graph.cpp`;与 P0 的 `bind` 调用兼容 |
| 插件 ABI 边界 | **提前锁定 `0.1`**。C ABI 导出面固定为 `ie_create_backend/ie_destroy_backend/ie_api_version`;`IE_API_VERSION_MAJOR=0`、`IE_API_VERSION_MINOR=1`,`ie_api_version()` 恒返回 `"0.1"`。插件以 `PluginMeta.api_version` 参与 `is_api_compatible` 检查(major 必须相等,minor 不得更新);P17 只补动态加载器,不改 ABI。 | `src/api/c_api/ie_api.h`、`src/core/plugin/plugin_api.h`、`plugin_registry.h` |
| IR 序列化 | **JSON 延后**。P0.5 不引入 JSON 库,`GraphExporter`/`MetricsExporter`/实验导出等全部返回 `Unsupported`;序列化格式留待 P15/P16 工具链里程碑再冻结。 | `src/observability/observability.h` |
| `KernelVariant` 结构 | **升级到设计 §6.2**。字段为 `name/target_kind/req/cost`;`Requirements` 七字段、`CostModel` 三字段;`KernelVariantRegistry::select` 按能力位、ρ 与显存/带宽/L3 阈值过滤。 | `src/core/tuning/kernel_variant.h`、`kernel_variant_registry.h` |
| `FeatureFlags` 位置 | 放在 **`src/core/config/feature_flags.h`**,并提供进程级 `global_feature_flags()`;通过 `EngineConfig::features` 与 `Experiment::Config::features` 传递。 | `src/core/config/feature_flags.h`、`engine_config.h` |
| `HybridConfig` / `ValidationConfig` 位置 | `HybridConfig` 从 `engine_config.h` 移入 **`src/hybrid/hybrid_config.h`**(§7.2 全字段);`ValidationConfig` 从 `engine_config.h` 移入 **`src/validation/config.h`**(§10.7 全字段)。`EngineConfig` 字段名 `hybrid`/`validation` 保持不变。 | `engine_config.h` 仅保留 include 与字段 |
| 无返回值结果类型 | **`Status` 是规范的 void 结果**。设计中写作 `Result<void>` 的接口(如转换、报告)统一映射为 `Status`;不新增 `Result<void>` 特化。 | `src/core/base/error.h` |
| 依赖边界 | P0.5 冻结不引入 MLIR、vcpkg、JSON、gRPC/protobuf、Google Benchmark;所有支撑层只声明接口/空实现。 | `CMakeLists.txt` 仅新增 `ie_c_api.cpp` 到 `ie_cpu` |
